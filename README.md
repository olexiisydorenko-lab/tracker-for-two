# Трекер Олі й Марка

Спільний фінансовий трекер на [Beancount 3](https://beancount.github.io/) і [Fava](https://beancount.github.io/fava/).
Домашнє завдання #3, Genesis Warsaw IT School 5.0. **У репозиторії лише штучні дані з завдання.**

- Марко відкриває трекер з телефона за посиланням (HTTPS), входить за паролем і бачить звіт за місяць:
  витрати за категоріями, норму заощаджень, фіксовані й змінні витрати.
- Готівку додає простою формою «Додати витрату готівкою» на головній сторінці: сума, категорія, опис, дата.
  Запис іде в `manual.beancount` у правильному для Beancount вигляді і одразу є у звіті (блок «Додано з телефона»).
  Fava на `/fava/` лишається для детального перегляду.

## Перевірка однією командою

```bash
pip install -r requirements.txt
python check.py
```

`check.py` перегенеровує облік з виписок, запускає `bean-check` (має мовчати) і друкує змінні витрати
за серпень і вересень. Очікуваний результат:

```
== bean-check ==
(тиша — помилок немає)

== Змінні витрати (без #fixed) ==
Оля    серпень     2195.21 зл  (контроль 2195.21)  OK
Оля    вересень    2582.42 зл  (контроль 2582.42)  OK
Марко  серпень     1855.57 зл  (контроль 1855.57)  OK
Марко  вересень    2432.83 зл  (контроль 2432.83)  OK
```

Код виходу 0 — усе збігається, 1 — є розбіжність.

## Як влаштовано

| Файл | Що робить |
| --- | --- |
| `data/olya-statement.csv`, `data/marko-statement.csv` | Штучні виписки з завдання (два банки, два формати) |
| `rules-olya.csv`, `rules-marko.csv` | Правила «продавець → категорія»; `так` у третій колонці = фіксована витрата |
| `import.py` | Читає обидва формати, пише `ledger/olya.beancount` і `ledger/marko.beancount` з перевіркою залишку на кожен день |
| `main.beancount` | Рахунки обох (`Assets:Оля:…`, `Expenses:Марко:…`), початкові залишки, збережені запити |
| `manual.beancount` | Операції, додані вручну (форма готівки або Fava). `import.py` його не перезаписує |
| `cash.py` | Форма готівки: перевіряє суму, категорію й дату, дописує запис, відкочує його, якщо облік не сходиться |
| `report.py` | Звіт за місяць для Олі або Марка; рендериться на кожен запит |
| `app.py` | Вхід за паролем, звіт на `/`, Fava на `/fava/`; усе, крім `/login`, закрито; секрети з `.env` |
| `wsgi.py` | Точка входу для gunicorn |
| `storage.py` | Зберігає `manual.beancount` у GitHub між перезапусками сервера |
| `render.yaml` | Налаштування сервісу на Render |
| `check.py` | Одна команда перевірки (див. вище) |

Фіксовані витрати мають тег `#fixed`: в Олі — оренда, ZTM, Netflix, Spotify, Claude.ai, Play;
у Марка — Orange, PGE, Zdrofit, YouTube Premium. Решта — змінні.

## Безпека

1. **Без входу трекер не показує жодних даних.** `AuthMiddleware` стоїть над усім застосунком, включно з Fava:
   без підписаної cookie будь-який шлях повертає 302 на `/login`.
2. **Паролі й ключі — лише у змінних середовища.** У коді й репозиторії їх немає: `TRACKER_PASSWORD`
   (або його хеш `TRACKER_PASSWORD_HASH`), `SECRET_KEY` і `GITHUB_TOKEN` задаються в Environment сервісу
   на Render; `SECRET_KEY` Render генерує сам. Локально — файл `.env`, який у `.gitignore`.
3. **Лише HTTPS.** Render віддає сайт тільки через HTTPS і перенаправляє HTTP; cookie входу має прапорці
   `Secure`, `HttpOnly`, `SameSite=Lax`; сервер шле HSTS.
4. **Лише штучні дані** — виписки з домашнього завдання.

Додатково: невдала спроба входу гальмує відповідь на 1 с, щоб ускладнити підбір пароля, а параметр
`next` після входу веде лише на цей сайт. `GITHUB_TOKEN` — fine-grained токен з доступом лише до цього
репозиторію, тож навіть у разі витоку він не дає доступу до інших. Двофакторний вхід і журнал доступу не
додавали: для двох людей і штучних даних вони коштують більше часу, ніж захищають.

## Чому ручні операції комітяться в GitHub

Безкоштовний Render не має постійного диска: після засинання сервіс стартує з файлів репозиторію.
Тому `storage.py` під час старту забирає `manual.beancount` з GitHub, а після кожного збереження у Fava
комітить його назад (з `[skip render]`, щоб не запускати повторний деплой). Без змінних `GITHUB_*`
модуль нічого не робить.

## Локальний запуск

```bash
pip install -r requirements.txt
cp .env.example .env    # заповніть хеш пароля і SECRET_KEY, додайте TRACKER_DEV=1
python app.py
```

Відкрийте http://127.0.0.1:5000.

## Деплой на Render (безкоштовно)

1. render.com → увійти через GitHub → **New → Blueprint** → вибрати цей репозиторій (`render.yaml`).
2. Заповнити змінні, позначені `sync: false`: `TRACKER_PASSWORD` і `GITHUB_TOKEN`
   (GitHub → Settings → Developer settings → Fine-grained tokens → лише цей репозиторій → Contents: Read and write).
3. Deploy. Збірка запускає `python check.py`, тож помилка в обліку зупиняє деплой.

## Що спрощено, щоб вміститися в безкоштовний тариф

- Один логін (Марко) замість окремих входів і приватних витрат для кожного — це фіча #12 з роадмапу.
- Звіт рахується на кожен запит, без кешу й фонових задач.
- Безкоштовний сервіс засинає без відвідувачів: перше відкриття може тривати до хвилини.
- Замість платного постійного диска ручні операції зберігаються комітами в цей репозиторій.
- Виписки імпортуються вручну (`python check.py`), без автозавантаження з банку.
